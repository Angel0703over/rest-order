# 上线验收清单：真机三端登录闭环

适用版本：`9a47335` 之后（含 `utils/cloudConfig.js` 入口开关修正）。

目标：在真机上确认 店长 / 员工 / 顾客 三条登录链路各自的入口页、权限边界与核心动作均符合预期，且不出现「停在顾客页」「误判无权限」两类历史问题。

## 0. 前置条件

| 项 | 检查方式 | 通过标准 |
|---|---|---|
| 云环境 ID | `utils/cloudConfig.js` 的 `CLOUD_ENV_ID` | 与云开发控制台环境 ID 一致 |
| 云函数已上传 | 开发者工具 → 云开发 → 云函数 | 15 个云函数均为「已部署」最新版本 |
| `users` 集合 | 云开发 → 数据库 | 已有店长记录，`openid` 为该微信号在小程序内的真实值 |

> **取 openid 的正确位置**：小程序运行后 console 里 `app cloud login session` 的 `openid`。不要用开发者工具「登录账号」的 openid——两者不同，用错会导致店长身份不生效。
| 其余集合 | 同上 | `members` / `memberLevels` / `categories` / `meals` / `settings` 均有数据 |
| 入口跳转开关 | `utils/cloudConfig.js` | `FORCE_CUSTOMER_ENTRY_OVERRIDE = false`（默认），否则店长/员工会被卡在顾客页 |
| 编译版本 | 开发者工具「真机调试」或「预览」 | 与当前代码一致，改代码后必须重新编译 |

> 体验版（`trial`）与正式版（`release`）会自动关闭代客下单开关，属预期行为，不是缺陷。

## 1. 店长链路（owner）

1. 用店长微信打开小程序，冷启动等待云登录完成。
2. **期望**：自动 `reLaunch` 至 `/pages/admin/home/index`，不再停留在 `/pages/index/index`。
3. 依次进入 7 个模块并确认可正常加载：门店配置、员工管理、餐食分类、餐食维护、会员等级、会员管理、今日订单。
4. 员工管理中点「新增员工」，保存后列表出现该员工，`staffId` 自动递增。

**失败判定**：停在顾客页 → 检查 `FORCE_CUSTOMER_ENTRY_OVERRIDE`；跳 `/pages/no-access/index` → 检查 `users` 中该 openid 的 `role` 是否为 `owner`。

## 2. 员工链路（staff）

1. 店长先在「员工管理」中新建该员工，**手机号必须填写**（`openid` 保持为空）。
2. 员工用自己的微信打开小程序 → 进入绑定页 → 授权手机号。
3. **期望**：绑定成功后落到 `/pages/staff/home/index`，工作台仅显示 分类 / 餐食 / 订单 三个模块。
4. 进入订单页，可将订单从 `已提交` 改为 `制作中`、`已完成`，并看到筛选标签与计数正常。
5. 手动访问 `/pages/admin/settings/index`、`/pages/admin/staff/index`。
6. **期望**：被导向 `/pages/no-access/index`，不得进入配置页。

**失败判定**：能进配置页 → 云函数侧权限校验异常（不能只靠前端隐藏入口）；绑定后仍跳顾客页 → 检查 `bindMemberPhone` 是否已重新部署；订单页空白 → 检查 `getStaffOrders` 是否部署。

> `bindMemberPhone` 已改为双分支（员工优先、会员其次）。**必须重新部署该云函数**，否则员工绑定不会生效。

## 3. 顾客链路（customer）

1. 用未绑定微信打开小程序（非店长/员工 openid）。
2. **期望**：进入 `/pages/bind-phone/index`，提示绑定会员手机号。
3. 授权手机号并输入一个 `members` 中存在的手机号 → 绑定成功 → 转 `/pages/index/index`。
4. 点单页确认：分类栏、餐食卡片、图片正常（云 fileID 失效时应回退默认 SVG 而非破图）；不可点餐食置灰。
5. 选择房间与桌号，提交订单 → 弹出下单成功弹窗 → 订单页可见该单。
6. 换一个已绑定其他微信的手机号重试绑定。
7. **期望**：提示该手机号已被绑定，拒绝重复绑定。

**失败判定**：绑定后仍跳绑定页 → 检查 `bindMemberPhone` 是否部署与 `members.phone` 是否一致。

## 4. 交叉验证

| 场景 | 操作 | 期望 |
|---|---|---|
| 店长代客下单 | 店长身份进入顾客页下单（开发版） | 下单成功；体验版/正式版应被拒绝（`当前身份不能提交顾客订单`） |
| 员工被停用 | 店长端将某员工设为停用，该员工再打开小程序 | 跳 `/pages/no-access/index` |
| 冷启动竞态 | 杀进程后立即打开管理页入口 | 不出现「无权限」闪现，会话就绪后正常放行 |
| 门店打烊 | 门店配置关闭营业，顾客提交订单 | 提示门店已打烊，订单不生成 |

## 5. 故障速查

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| 一直停在顾客页 | `FORCE_CUSTOMER_ENTRY_OVERRIDE = true` | 改回 `false` 并重新编译 |
| 登录后退化为顾客 | `users` 无该 openid 或 `role` 写错 | 用 `scripts/generate-users-seed.js` 重新生成并 Upsert 导入 |
| 门店配置/餐食为空 | 集合未导入种子 | 按 `cloud-development.md` 导入 `*.import.json` |
| 订单页无数据 | 云函数未部署或 `orders` 集合缺失 | 上传云函数，创建 `orders` 集合 |
| 图片破图 | 云存储 fileID 失效 | 属兜底路径验证点，确认是否回退到 `/assets/meal-bowl.svg` |
